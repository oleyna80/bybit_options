- **PostgreSQL + TimescaleDB** (уже настроен в docker-compose.yml)

**Зависимости**:

## Технические детали

### Формула IV Rank
```
IV Rank = (Current IV - Min IV over 30 days) / (Max IV over 30 days - Min IV over 30 days) * 100
```
Где:
- Current IV – подразумеваемая волатильность ATM опциона с ~30 дней до экспирации
- Min IV, Max IV – минимум и максимум за последние 30 календарных дней

### Источники данных
- **Цена**: Bybit API `/v5/market/kline` (category=linear, symbol=BTC-PERPETUAL, interval=D)
- **IV**: Bybit API `/v5/market/historical-implied-volatility` (baseCoin=BTC, period=30)
- **Бэкфилл**: Для 5-летней истории можно использовать Tardis.dev/Laevitas (опционально) или сгенерировать синтетические данные для демо.

### Стек технологий
- **Бэкенд**: Python 3.x, FastAPI, SQLAlchemy, TimescaleDB, Bybit API
- **Фронтенд**: React 18, TypeScript, Vite, Recharts, Tailwind CSS
- **База данных**: PostgreSQL 14 + TimescaleDB extension
- **Контейнеризация**: Docker, docker-compose

## Оценка рисков
1. **Ограничения Bybit API**: исторические данные могут быть доступны только за 2 года (бесплатный тариф). Необходимо предусмотреть fallback на мок-данные или покупку премиум-доступа.
2. **Производительность TimescaleDB**: большие объёмы данных (5 лет × 365 дней × несколько таблиц) требуют оптимизации индексов и использования гипертаблиц.
3. **Синхронизация времени**: расчёт IV Rank зависит от полноты данных за предыдущие 30 дней. Необходима обработка пропущенных дней.
